# Template configuration and verification map

The template is already extracted. Use this map for setup and portability audits, not as evidence that a new account is configured.

| Area                  | Maintained seam                                                                                        | Verify                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Public identity/theme | `src/lib/store-config-values.ts`, public logo/favicon, home assets                                     | Brand, voice, navigation, metadata, support and visuals agree; placeholder gates cleared only after review.                                  |
| Canonical origin      | `NEXT_PUBLIC_SITE_URL`, `src/lib/get-site-url.ts`                                                      | Permanent HTTPS production origin and rebuilt public variables; no other store fallback.                                                     |
| Credentials           | `.env.example`, ignored `.env.local`, deployment secrets                                               | Correct accounts/environments; no secrets in source/client state or setup progress.                                                          |
| Database              | `supabase/migrations/`, restricted `store_app_runtime`                                                 | Clean migrated store; no sample inventory/admin/garments; separately provisioned password and real runtime grants.                           |
| Admin/library         | [Access](../../../../docs/admin-auth.md), [library](../../../../docs/admin-design-library.md)          | First owner, email/passkeys, scoped grants, private asset protection and revocation.                                                         |
| First product         | [Product skill](../../store-printify-product/SKILL.md)                                                 | Explicit model/provider/profile; explicit verified first-product recipe; published donor needed only for UI/proposals.                       |
| Catalog               | [Catalog](../../../../docs/printify-catalog.md), admin Categories/Garment models                       | Complete per-store profiles before visibility; no product ID mapping required for normal publication.                                        |
| Publication/images    | [Publishing](../../../../docs/printify-publishing.md), [artwork](../../../../docs/artwork-previews.md) | Signed event, durable snapshot, hosted mockups and exact immutable approved-artwork revision.                                                |
| Checkout identity     | Checkout creation, fulfillment, paid verification, conversion validators                               | Immutable commerce.identity and shipping arithmetic; sandbox cannot manufacture an order. Preserve saved identities during later rebranding. |
| Shipping/policies     | Configured commerce values, [delivery](../../../../docs/delivery-expectations.md), policy pages        | Owner-confirmed amounts and estimates; supported destinations, cart, feeds, structured data and external merchant policies agree.            |
| Workers/monitor       | `scripts/vercel-crons.example.json`, `vercel.json`, GitHub monitor                                     | Host supports reviewed schedule/cost; authenticated production execution and meaningful monitor signal.                                      |
| Analytics             | [Meta](../../../../docs/meta-pixel.md), [Google](../../../../docs/google-conversions.md)               | Own destinations, opt-in configuration, current consent/GPC, no capability URL leaks; dashboard receipt separately checked.                  |
| Recovery/state        | Ignored `.store-setup.local.json`, database receipts/reservations                                      | Exact resume point, no secrets, no repeated uncertain provider creates.                                                                      |
| Portability checks    | `pnpm check:template`, `pnpm setup:check`, `pnpm setup:check --sandbox`, `pnpm setup:check --launch`   | Hygiene/configuration only; remote verification remains explicit.                                                                            |

A new empty store and an operating-store rebrand are different tasks. Never reset operational history or change pending-order metadata identities as part of ordinary theme work. Apply a minimal second-brand substitution trial when changing these seams.
