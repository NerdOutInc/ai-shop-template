# Store workflow skill catalog

These project skills describe this template's setup and operating workflows. They link to maintained code/runbooks instead of embedding accounts, credentials or past inventory as defaults. Check current provider interfaces and requirements when using them.

Start new-store setup with [store-setup](../../store-setup/SKILL.md), [confirmed defaults](store-defaults.md) and the [per-owner intake](../../store-owner-handoff/references/owner-intake.md). Defaults capture the reusable product and store model; intake captures each owner's delegation, business choices and actual approvals. Unanswered operations and launch-timing choices remain explicitly open.

| Skill                                                                 | Use it for                                                                                            | Completion evidence                                                                                                          |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| [store-setup](../../store-setup/SKILL.md)                             | Agent-led interview, visual direction, provider configuration and resumable onboarding.               | Non-secret state, configured brand, verified connections and explicit live gaps.                                             |
| [store-design-concepts](../../store-design-concepts/SKILL.md)         | Explore a shirt idea or collection, review a favorites gallery, then add selected designs when asked. | Exact count, private asset hashes/downloads, permanent numbers, personal pinned revisions and reconciled operation receipts. |
| [store-admin-access](../../store-admin-access/SKILL.md)               | Private-library owner setup, roles, sign-in and scoped agent access.                                  | Verified intended admin/grant, private asset denial after revocation, and explicit device/email checks.                      |
| [store-design-recovery](../../store-design-recovery/SKILL.md)         | Interrupted generation, unavailable artwork, pinned selections and uncertain product drafts.          | Exact recovered revisions/receipts and unresolved items retained without substituted art or duplicate listings.              |
| [store-printify-product](../../store-printify-product/SKILL.md)       | Approved transparent artwork, product creation, placement and curated variants.                       | Saved product, file identity, alpha/placement/prices, previews and fresh draft or authorized publication status.             |
| [store-google-merchant](../../store-google-merchant/SKILL.md)         | Merchant account, domain verification/claim, feed and diagnostics.                                    | Separate ownership, claim, fetch/import, variant/image match and approval results.                                           |
| [store-stripe-checkout](../../store-stripe-checkout/SKILL.md)         | Hosted Checkout and signed webhook setup.                                                             | Storefront sandbox payment, durable simulated order, event replay, correct environment and no Printify order.                |
| [store-owner-handoff](../../store-owner-handoff/SKILL.md)             | Exact owner instructions, then resume and verify.                                                     | Correct page/account, minimal task, completion signal and saved-state readback.                                              |
| [store-publishing-recovery](../../store-publishing-recovery/SKILL.md) | Connect/operate publishing and resolve catalog synchronization failures.                              | Durable job, snapshot, acknowledgment, storefront membership and monitor result.                                             |

| [store-launch-verification](../../store-launch-verification/SKILL.md) | Environment diagnosis and local/preview/production readiness.                                         | Layered evidence, exact deployment and explicit unverified live steps.                                                       |
| [store-template-readiness](../SKILL.md)                               | Audit safe reuse, hygiene and second-brand readiness.                                                 | Dependency map, configuration inputs, new-store boundaries and second-brand acceptance criteria.                             |

These skills expect this repository layout and are included with this template. Provider-wide skills are discovered from the agent host when needed; the template does not bundle provider skill copies that can go stale.

For an owner with an idea rather than finished files, start with `store-design-concepts`: generate the requested alternatives, deliver the review gallery, and preserve its permanent design numbers and personal revision-pinned favorites in the database. A later “add my favorites” continues into `store-printify-product` using the exact selected PNGs and existing store choices. Bringing approved artwork is another valid entry point; generation is not a prerequisite.

The publishing skill includes [Blob image operations](../../store-publishing-recovery/references/product-images.md): new-store binding, immutable mockup uploads, exact approved-artwork derivatives pinned to publication snapshots, frozen-snapshot mockup backfill, partial recovery and direct-image verification. This workflow is implemented; rollout evidence must still be checked for the target environment.

## Portable photography skills

[store-model-casting](../../store-model-casting/SKILL.md) creates and preserves fictional identities; [store-garment-photography](../../store-garment-photography/SKILL.md) directs exposures and fits original artwork to garments with reviewed placement and cloth response. These two packages work outside this repository and contain no shop's models or artwork. See [installation and prerequisites](../../../../docs/portable-photo-skills.md). The other operational skills above retain their repository-specific contracts.

## Further skills to consider after real use

| Candidate                         | When to extract it                                                                                                                                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Multi-channel catalog feeds       | When repeated channel onboarding or recovery merits its own skill: reuse the shared published catalog and stock rules, then apply the target channel's requirements and diagnostics.                 |
| Pricing and fulfillment economics | When setting another brand's prices: compare variant costs, customer/provider shipping, payment fees and the owner's margin target using current inputs and explicit assumptions.                    |
| Store customer operations         | After confirming support/refund/return processes: triage delivery and print issues, draft policy-consistent replies and track authorized resolutions. Sending messages needs explicit authorization. |
| Approved art to marketing assets  | When repeated: reuse selected art/mockups in requested formats, preserve provenance and exact concept counts, keep exploration galleries out of production changes.                                  |

Extract a workflow when its non-obvious decisions recur, inputs are clear, and completion can be checked. More skill folders are not a substitute for a working store.
