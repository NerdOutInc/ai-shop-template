# Intake for a new store owner

Start with [confirmed template defaults](../../store-template-readiness/references/store-defaults.md). This is a reusable intake, not a file for storing real credentials or private owner details. Save actual answers in the store's appropriate configuration or authorized private project context, keeping secrets in the intended secret store.

Resolve available answers from the current task and verified accounts first. Ask concise, grouped questions only when the next work depends on them. Carry answers across product batches and sessions; do not ask the owner to approve the same ordinary action twice. Missing does not mean delegated.

Use three states for each relevant input: **confirmed**, **delegated with rule**, or **unanswered**. Keep actual execution state separate: an approved account setup is not a verified connection, and an approved launch is not a successful launch.

Useful first prompt when delegation is unknown: “For this batch, which choices should I make for you—colors, placement, names, descriptions and mockups—and which have you already chosen?” Ask about prices separately if the owner's policy is missing. If the user says to add the batch and the necessary rules are known, perform the full batch and report its results; do not schedule another approval meeting with the shirts.

Treat saved decisions and receipts as context, not fresh authorization. Reuse actual owner instructions within their established scope; confirm missing or conflicting scope without repeating already-authorized decisions.

For a launch with delayed external checks, prepare a receipt such as: “Checkout and the paid order are verified. Sample inspection and Google approval are still pending. The next decision is whether to wait or open with those two checks outstanding.” Present the actual launch and purchase-test actions for explicit approval when needed; never infer either approval from completion of setup.

Confirm the store’s IANA time zone and weekly feature day/time. Save them in `src/lib/store-config.ts` as `timeZone` and `weeklyFeature` (`weekday`: Sunday 0 through Saturday 6). The template’s neutral default is Monday 09:00 UTC; delivery business dates and admin date displays also use the configured zone.
